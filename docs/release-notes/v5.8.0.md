# DupeZ v5.8.0

Current audited disposition: [v5.8.0 release-candidate status](RC_STATUS_v5.8.0.md).

DupeZ v5.8.0 promotes the repaired bounded-resilience architecture from
v5.7.9 and tightens performance, AI overload handling, dependency scope, and
release repeatability.

## Highlights

- Standard effects are owned by the pinned Kalirenegade Clumsy process.
- Native WinDivert hosts only namespaced DupeZ extensions, including the
  bounded Connection Resilience and experimental Pulse Resilience labs.
- One process-wide owner prevents competing packet engines and preserves the
  lease whenever shutdown cannot be confirmed.
- Periodic traffic snapshots are coalesced away from the packet capture
  thread, keeping capture responsive during analysis windows.
- Smart Ops accepts at most two simultaneous provider calls and uses the
  validated offline advisor during overload or provider failure.
- Unused pandas and its release weight are removed; XLSX import/export still
  uses openpyxl and the optional audio/model paths retain NumPy.
- The disposable packaging environment is `.release-venv`, avoiding the
  reproducible IDE formatter lock seen with `.build-venv`.
- Release preflight now rejects version drift in the active PowerShell/CMD
  drivers and GitHub release workflows.
- The logged UAC finalizer preserves native stderr diagnostics and decides
  success from the protected child exit code, so PyInstaller warnings cannot
  terminate an otherwise successful release build.
- Split-helper authentication resolves the token sentinel from Windows' real
  Local AppData profile on both sides of UAC, including isolated frozen tests.
- Frozen map startup no longer falls into Chromium's obsolete
  `--use-gl=swiftshader` path. The DXGI probe now decodes adapter records with
  typed unsigned fields, fixing the signed-byte conversion failure on current
  Windows systems where WMIC is absent. Auto enables ANGLE/D3D11 only after a
  successful probe and otherwise passes `--disable-gpu` for CPU rendering,
  eliminating the unsupported-flag `0xC0000409` fast-fail.
- Nested release-phase failures now propagate to the launcher and remain
  failed instead of being recorded as complete.
- Frozen dashboard automation now uses Windows' complete native `INPUT` union,
  and process-family cleanup preserves the original lifecycle result. The
  validator rebinds Qt's current dashboard
  handle before each shortcut when a runtime transition recreates the window,
  and activates it through the documented Windows input-queue boundary.
- Frozen GUI/WebEngine evidence now runs under the shipped safety dry-run mode
  and records that boundary in a fail-closed v3 schema. Privileged helper and
  packet-engine behavior remain separate mandatory exact-artifact manual and
  exact-commit hardware gates, so an unattended UAC prompt can no longer make
  GUI lifecycle evidence ambiguous.
- Canonical variant builds now fail noninteractively, so a blocked executable
  or packaging error returns immediately instead of waiting at a hidden prompt.
- Trusted plugin manifest v2 signs the complete directory inventory, including
  helper modules and resources. Added, missing, modified, linked, or generated
  bytecode files fail closed, and the loader re-verifies immediately before
  import. Minimum host versions are enforced with strict SemVer, failed
  activation is rolled back, and older entry-only manifests require re-signing.
- The elevated GUI authenticates the unelevated map child with a per-launch
  challenge and verifies the child PID owns the supplied HWND before any
  privileged reparenting operation.
- Backup restore advances authenticated persistence generations, while lock,
  SBOM, VEX, and vulnerability-review parsing now share one fail-closed exact
  pin and marker contract.
- Standard builds Authenticode-sign only a verified staged copy of the
  upstream Clumsy executable. PE source-equivalence, measured signer identity,
  distribution provenance, and independent frozen-archive inspection prevent
  an unrelated signed child from entering either variant.
- Hardware evidence is authenticated by exact workflow artifact ID and digest,
  and validated release files are uploaded from a private read-locked snapshot
  whose captured hashes are checked again after draft download.
- Cut-chain configuration, automatic kill-switch settings, sealed audit-webhook
  management, and redacted diagnostics export are now reachable through the
  desktop UI instead of remaining backend-only features.
- Update launch uses Windows Attachment Services and a final locked recheck;
  release tooling is bound to exact manifest-pinned ISCC/SignTool bytes and
  canonical remote `main` is rechecked before draft, upload, and publication.
- Distribution builds now generate and immediately verify a deterministic
  exact-lock third-party notice payload, install the project/source/relink
  records, and bind a `git archive` source ZIP from the exact clean commit into
  the checksum list and release attestation. Unresolved owner license/IP
  decisions remain a hard build stop.

## Safety boundary

DupeZ is for private servers, devices and networks you own, or environments
where you have explicit authorization. Bounded extensions release
automatically below 30 seconds, fail open on deadline/overflow, and do not
promise immunity from a game or server timeout.

## Release validation

The public artifacts are ready only after all of the following pass against
the exact v5.8.0 commit and bytes:

1. Owner-approved project terms compatible with the exact PyQt binding license,
   all license/IP evidence decisions recorded, protected `main` and
   `production-release` controls, then full automated tests and the
   path-unfiltered source release preflight.
2. Hermetic GPU and Compat builds from hash-pinned locks.
3. Frozen import-boundary verification for both executables.
4. Non-admin GPU and admin Compat runtime validation.
5. Authorized hardware smoke evidence bound to the exact commit, locked source
   native provenance hashes, successful workflow artifact ID/digest, and the
   manual validation record. Target IP, MAC, and CIDR are excluded.
6. Defender scan, SHA-256 list, SBOM, clean lock-bound vulnerability review,
   provenance, updater sidecars, project license, deterministic third-party
   notice manifest, source/relink record, and exact-commit source archive.
   OpenVEX is emitted only for actual findings, which block the release. The
   review must match the canonical PyPI project/version responses and remain
   within the 24-hour preflight window.
7. Draft-release download and hash verification before publication.

Existing v5.7.9 installations may upgrade through the signed updater path
when v5.8.0 is published with valid updater sidecars. If the public build is
explicitly unsigned, Windows publisher warnings remain expected, the release
page must disclose that fact, and installation is manual: the production
updater deliberately refuses to auto-launch an installer without the trusted
Authenticode identity bound by its signed manifest.
